# 한성대학교 예약 시스템 개선 확장 프로그램

이 프로젝트는 한성대학교의 장비 및 공간 예약 시스템의 사용자 경험(UX)을 개선하기 위해 개발된 Chrome 및 Edge 브라우저 확장 프로그램입니다. [React](https://react.dev/), [TypeScript](https://www.typescriptlang.org/), 그리고 브라우저 확장 프로그램 개발 프레임워크인 [WXT](https://wxt.dev/)를 사용하여 구축되었습니다.

본 확장 프로그램은 기존의 장비(goods) 및 공간(space) 예약 페이지의 UI를 React 기반의 현대적이고 사용자 친화적인 인터페이스로 교체하여 전반적인 사용성을 향상시킵니다. 또한 학교 홈페이지에 사이드 패널을 toggle 형태의 사이드 패널을 이식하여 계정별 맞춤 예약 정보 및 빠른 링크 리스트를 한눈에 볼 수 있게 도와줍니다.

## 🚀 다운로드 및 실행 절차

### 1. 소스 코드 복제

먼저, Git을 사용하여 프로젝트의 소스 코드를 로컬 컴퓨터로 복제합니다.

```bash
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```
> 참고: `https://github.com/USERNAME/REPOSITORY.git`는 실제 프로젝트의 Git 주소로 변경해주세요.

### 2. 의존성 설치

프로젝트에 필요한 라이브러리 및 도구를 설치합니다. 프로젝트 루트 디렉토리에서 다음 명령어를 실행하세요.

```bash
npm install
```

### 3. 개발 서버 실행

핫 리로딩(hot reloading)을 지원하는 개발 서버를 시작합니다. 코드가 변경될 때마다 확장 프로그램이 자동으로 다시 빌드됩니다.

```bash
npm run dev
```

### 4. 브라우저에 확장 프로그램 로드

개발 서버가 실행되면 `.output/chrome-mv3-dev` 디렉토리에 개발용 빌드 파일이 생성됩니다. 이 파일을 브라우저에 로드해야 합니다.

**Chrome/Edge 기준:**
1. 브라우저 주소창에 `chrome://extensions` 또는 `edge://extensions`를 입력하여 확장 프로그램 관리 페이지로 이동합니다.
2. 우측 상단의 **'개발자 모드'**를 활성화합니다.
3. **'압축 해제된 확장 프로그램을 로드합니다'** 버튼을 클릭합니다.
4. 파일 탐색기가 열리면, 이 프로젝트의 `.output/chrome-mv3-dev` 디렉토리를 선택합니다.
5. 확장 프로그램이 로드되고, 이제 한성대학교 관련 페이지에 접속하여 테스트할 수 있습니다.

## 🛠️ 빌드 및 배포

### 프로덕션 빌드

배포를 위한 프로덕션 빌드를 생성하려면 다음 명령어를 실행하세요.

```bash

```

최적화된 프로덕션 빌드 파일이 `.output/chrome-mv3` 디렉토리에 생성됩니다.

프로덕션 빌드를 배포용 zip 파일로 만들려면 다음 명령어를 사용하세요.

```bash

```

이 명령어는 프로젝트의 루트 디렉토리에 압축 파일을 생성합니다.

## ⚙️ 개발 컨벤션

### 코드 스타일

- **TypeScript**: 타입 안전성을 위해 TypeScript를 사용합니다.
- **React**: 모든 React 컴포넌트는 훅(hooks)을 사용하는 함수형 컴포넌트로 작성합니다.
- **스타일링**: 스타일은 주로 React 컴포넌트 내의 **인라인 스타일**을 사용하여 작성합니다. 이는 컴포넌트 스타일을 캡슐화하고, 호스트 페이지의 CSS와 충돌을 피하기 위한 의도적인 선택입니다.
- **파일 이름 규칙**:
    - 컴포넌트: `PascalCase.tsx` (예: `GoodsItem.tsx`)
    - 페이지: `PascalCasePage.tsx` (예: `GoodsListPage.tsx`)
    - 서비스/API: `camelCase.ts` (예: `goodsApi.ts`)

### 데이터 흐름

1.  **콘텐츠 스크립트** (예: `entrypoints/goods.content.ts`)가 한성대학교 웹사이트의 대상 페이지에 주입됩니다.
2.  콘텐츠 스크립트는 페이지의 DOM에서 필요한 데이터를 **스크래핑**합니다.
3.  스크래핑된 데이터는 **React 페이지 컴포넌트** (예: `src/pages/goods/GoodsListPage.tsx`)에 props로 전달됩니다.
4.  React 컴포넌트는 원래 페이지의 콘텐츠를 대체하여 새로운 사용자 인터페이스를 렌더링합니다.
5.  **서비스** (예: `src/services/goodsApi.ts`)는 데이터 가져오기, 파싱 및 기타 비즈니스 로직을 처리하는 데 사용됩니다.

## 📁 프로젝트 구조

프로젝트는 각 기능별로 역할을 분리하는 디렉토리 구조를 따릅니다.

- `entrypoints/`: 콘텐츠 스크립트(`.content.ts`), 백그라운드 스크립트(`background.ts`), 새 탭 페이지, 팝업 등 확장 프로그램의 진입점을 포함합니다.
- `src/`: React 애플리케이션의 핵심 소스 코드를 포함합니다.
    - `components/`: 재사용 가능한 React 컴포넌트.
    - `pages/`: 콘텐츠 스크립트에 의해 렌더링되는 최상위 페이지 컴포넌트.
    - `services/`: 비즈니스 로직, API 상호작용 및 데이터 처리를 담당합니다.
- `wxt.config.ts`: 매니페스트 속성, 권한 및 기타 설정을 정의하는 WXT 프레임워크의 메인 설정 파일입니다.
